# DevTrust - Платформа бизнес-приложений по подписке

## Идея проекта

DevTrust — это единая платформа-магазин для управления бизнес-приложениями по подписке. Проект представляет собой маркетплейс SaaS-приложений, где компании могут находить, тестировать и подписываться на различные бизнес-инструменты (CRM, аналитика, документооборот, HR-системы и т.д.) через единый интерфейс с консолидированной оплатой.

### Ключевые особенности:
1. **Единая точка доступа** — все приложения доступны через одну платформу
2. **Упрощенная оплата** — единый счет за все подписки
3. **Централизованное управление** — контроль доступа сотрудников, мониторинг использования
4. **Безопасность** — SSO, аудит, контроль данных
5. **Экосистема** — интеграции между приложениями, общие данные

### Целевая аудитория:
- Малый и средний бизнес (SMB)
- Крупные предприятия с децентрализованными IT-потребностями
- IT-директора и руководители отделов
- Разработчики приложений (как поставщики)

## Архитектура системы

### Технологический стек:
- **Frontend**: Next.js 14 (App Router), TypeScript, Tailwind CSS
- **Backend**: Next.js API Routes, Prisma ORM
- **База данных**: PostgreSQL
- **Кэширование**: Redis
- **Хранение файлов**: MinIO (S3-совместимое)
- **Аутентификация**: NextAuth.js
- **Платежи**: Stripe
- **Мониторинг**: Sentry
- **Контейнеризация**: Docker, Docker Compose

### Монолитная архитектура с монорепозиторием:
- `apps/web` — основной веб-интерфейс магазина
- `packages/core` — общие утилиты и типы
- `packages/app-template` — шаблон для разработчиков приложений
- `design-system` — дизайн-система и компоненты

## API Endpoints

### Аутентификация
- `POST /api/auth/[...nextauth]` — NextAuth handlers
- `POST /api/register` — регистрация
- `POST /api/login` — вход
- `POST /api/forgot-password` — запрос сброса пароля
- `POST /api/reset-password` — установка нового пароля
- `POST /api/verify-email` — подтверждение email

### Приложения
- `GET /api/catalog/search` — поиск в каталоге
- `GET /api/apps/[slug]/status` — статус приложения
- `POST /api/apps/[slug]/install` — установка приложения

### Биллинг
- `POST /api/checkout` — создание checkout сессии
- `POST /api/billing/portal` — портал управления подписками
- `POST /api/webhooks/stripe` — вебхуки Stripe

### Внутренние API
- `GET /api/internal/me` — информация о текущем пользователе
- `GET /api/internal/organization` — текущая организация
- `GET /api/internal/check-access` — проверка доступа к приложению
- `GET /api/internal/usage` — статистика использования

### SSO
- `POST /api/sso/init` — инициализация SSO
- `POST /api/sso/verify` — верификация токена
- `POST /api/sso/refresh` — обновление токена

### Отзывы
- `POST /api/reviews` — создание/обновление отзыва

### Промокоды
- `POST /api/promo/validate` — валидация промокода

## База данных (Prisma Schema)

### Основные модели:

1. **User** — пользователи системы
2. **Organization** — организации/компании
3. **Membership** — связь пользователей с организациями
4. **App** — приложения в каталоге
5. **AppCategory** — категории приложений
6. **Plan** — тарифные планы
7. **Subscription** — подписки организаций
8. **AppAccess** — доступ пользователей к приложениям
9. **Review** — отзывы о приложениях
10. **Invoice** — счета
11. **Notification** — уведомления
12. **AuditLog** — логи аудита
13. **Post** — статьи блога
14. **PromoCode** — промокоды
15. **Bundle** — наборы приложений

## Бизнес-логика

### Процесс покупки приложения:
1. Пользователь выбирает приложение в каталоге
2. Выбирает тарифный план (бесплатный/платный)
3. Применяет промокод (если есть)
4. Перенаправляется в Stripe Checkout
5. После успешной оплаты создается подписка
6. Настраивается доступ к приложению
7. Пользователь получает уведомление

### Процесс установки приложения:
1. После активации подписки
2. Система создает поддомен для приложения
3. Настраивает SSO интеграцию
4. Предоставляет доступ выбранным пользователям
5. Отправляет приветственное письмо

### Реферальная система:
1. Пользователь получает уникальный реферальный код
2. Приглашает других пользователей
3. За каждую успешную регистрацию получает бонусы
4. Бонусы можно использовать для оплаты подписок

## Безопасность

### Меры защиты:
1. **Аутентификация** — NextAuth с сессиями
2. **Авторизация** — ролевая модель на уровне middleware
3. **Валидация данных** — Zod схемы на клиенте и сервере
4. **Rate limiting** — ограничение запросов к критичным endpoint'ам
5. **SQL injection protection** — Prisma ORM
6. **XSS protection** — экранирование вывода, CSP headers
7. **CSRF protection** — встроено в Next.js
8. **Аудит** — логирование всех значимых действий
9. **Шифрование** — bcrypt для паролей, HTTPS для трафика

## Масштабирование

### Горизонтальное масштабирование:
1. **База данных** — репликация PostgreSQL
2. **Кэш** — Redis кластер
3. **Файловое хранилище** — MinIO распределенное
4. **Веб-серверы** — несколько инстансов Next.js за балансировщиком

### Вертикальное масштабирование:
1. **Оптимизация запросов** — индексы в БД
2. **Кэширование** — Redis для частых запросов
3. **CDN** — для статических файлов и изображений
4. **Асинхронные задачи** — очереди для фоновых процессов

## Заключение

DevTrust представляет собой комплексную платформу для управления SaaS-экосистемой, которая решает проблему фрагментации бизнес-приложений. Проект сочетает в себе удобство маркетплейса с мощностью корпоративной платформы, предлагая бизнесам единое решение для поиска, подключения и управления всеми необходимыми инструментами.

Платформа построена на современных технологиях с акцентом на безопасность, масштабируемость и пользовательский опыт, что делает ее конкурентоспособным решением на рынке B2B SaaS.
